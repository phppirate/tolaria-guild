# Pilot Bot

- #pilot #ideas #ai


All right, the most recent idea I've had is a pilot bot that runs on the application and can interact with people, do tasks, and also monitor project inboxes. When a project email comes in, the bot is able to read it and see what needs to be done with it. If there's an actionable item, it can alert the project manager and also draft a reply based on project data and that kind of thing.

Really, the big thing that we need to be thinking about here is how much AI can handle on its own and take off the plates of project managers, so that they don't have to worry about it or so that they can be more productive when it comes to the actual work that requires their attention.

It could even use the task system inside the application, with the bot as one of the users. You could just assign a task to the bot, and then, if you have it set for a certain time, a reminder can trigger the bot to do it at that time. It could handle things like invoicing, checking for new files, and got-it calls. All of that kind of stuff could probably be handled directly using a bot.

The big one that will be invaluable, though, is obviously the permit status checks. If we can get it so that the bot is able to log into the permitting portals, check whether something is completed or needs work, or whether there are any actionable items, and then report back to the project manager, that would be extremely valuable.

Maybe we look into a third-party integration for Grokbot and Pallet so that we can offer things like reviews and that kind of thing. Otherwise, we could build the functionality right into Pallet and connect to Pallet's own MCP server directly there.

One of the things that could be absolutely invaluable is AI-populated due diligence and AI letters of transmittal. I think AI letters of transmittal are really low-hanging fruit, and we could probably have that done in a day.

We could even have the bot be the search function or something like that, and you just start asking your question. We pass the context in depending on where you are in the application. If you're viewing an invoice, that context would be passed through. If you're viewing a task, that context would be passed through, and so on and so forth.
